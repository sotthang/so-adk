> 검토 주체 명기: 이 검토는 `so-reviewer` 에이전트가 아니라 세션의 메인 스레드가 수행했다. SPEC 작성자와 검토자가 동일하므로 독립성이 없다 — 저자가 놓친 전제를 잡아내는 검토의 본래 가치는 제한적이다. 아래 M-1은 SPEC 본문이 제시한 정규식을 반례로 실행해 확인한 것이며, 판단이 아니라 실측이다.

## M-1 (Major) — R1의 정규식이 R2가 금지한 실패 모드를 재도입한다

**지적**: R1이 제시한 판별식 `^SPEC-[0-9]{3}-[^.]+\.md$`은 3자리 숫자를 강제한다. 그 결과 **자릿수가 규칙에 맞지 않는 진짜 SPEC 본문이 조용히 누락**된다.

실측 (반례를 실제로 실행):

| 파일명 | R1 원안 | 대안 `^SPEC-[^.]+\.md$` | 기대 |
| ------ | ------- | ----------------------- | ---- |
| `SPEC-001-plugin-migration.md` | 포함 | 포함 | 포함 |
| `SPEC-001-plugin-migration.arch.md` | 제외 | 제외 | 제외 |
| `SPEC-001-plugin-migration.review-v3.md` | 제외 | 제외 | 제외 |
| `SPEC-003-a.design.md` (장래 동반 문서) | 제외 | 제외 | 제외 |
| **`SPEC-1-foo.md`** | **제외** ❌ | 포함 | **포함** |
| **`SPEC-0001-foo.md`** | **제외** ❌ | 포함 | **포함** |

**왜 Major인가**: SPEC 본문의 R2는 *"Status 라인 부재를 배제 기준으로 삼지 않는다 — 진짜 미완료 SPEC이 형식 오류 때문에 조용히 누락되는 반대 방향 결함이 생긴다"* 고 명시적으로 금지한다. R1의 원안은 **동일한 실패 모드를 파일명 형식 쪽으로 우회 도입한다.** 자릿수 오타 하나로 진행 중인 작업이 재개 안내에서 사라지며, 증상이 없어 발견되지 않는다. 본 SPEC이 고치려는 결함(무성 오보고)보다 무성 누락이 더 나쁘다.

**조치**: 판별식을 `^SPEC-[^.]+\.md$`로 교체한다. 동반 문서 배제라는 목적은 그대로 달성한다 — 동반 문서는 `.md` 앞에 점이 하나 더 있고 `[^.]+`가 그 점을 넘지 못하기 때문이다. **자릿수 검증은 이 훅의 책임이 아니다**(훅은 재개 안내를 만드는 것이지 명명 규칙을 강제하는 도구가 아니다). 부수 효과로 판별식이 더 단순해진다.

## m-1 (Minor) — AC-R3c의 성격 명시

AC-R3c(`jq` 부재 폴백)는 본 SPEC이 도입하는 동작이 아니라 **기존 동작의 보존 확인**이다. R3가 "그 외 동작을 보존한다"로 규정하고 있으므로 AC 자체는 유효하나, 신규 기능 검증으로 오독될 수 있다. 회귀 방지 목적임을 AC 문언에 한 마디 붙이면 충분하다.

## m-2 (Minor) — Technical Approach의 예시 코드가 M-1과 함께 갱신되어야 함

Technical Approach의 스니펫이 R1 원안의 정규식을 그대로 담고 있다. M-1 수정 시 함께 갱신하지 않으면 요구사항과 설계가 어긋난다.

## 확인된 사항 (지적 아님)

- **이식성**: `[[ =~ ]]`와 `[^.]` 문자군이 macOS 기본 `/bin/bash` **3.2.57**에서 정상 동작함을 실행 확인했다. 훅의 shebang이 `#!/usr/bin/env bash`이므로 새 의존이 아니다.
- **대소문자**: bash의 글로브는 파일시스템의 대소문자 구분과 무관하게 `readdir` 결과를 대소문자 구분 매칭한다. macOS의 대소문자 무시 파일시스템에서도 `spec-001-foo.md`가 `specs/SPEC-*.md`에 걸리지 않으므로 플랫폼 간 동작 차이는 없다.
- **`specs/` 부재**: `shopt -s nullglob`이 이미 설정돼 있어 루프가 돌지 않고 `PENDING`이 빈 채로 exit 0 — 기존 동작이 보존된다.
- **`specs/archive/`**: 현행 글롭이 하위 디렉터리로 내려가지 않으므로 R1이 요구한 "계속 대상 밖" 조건은 코드 변경 없이 성립한다. AC-R1b가 이를 회귀 방지로 고정하는 것은 적절하다.
- **R4의 명분**: `session-start-resume.sh`의 동작 테스트가 0종이고 `post-edit-check.sh`는 4종이라는 비대칭은 실물 확인했다(`tests/run-checks.sh`의 훅 관련 검사는 존재·실행권한 검사뿐).
